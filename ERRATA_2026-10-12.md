# Erratum — October 12, 2026: hippocampal source-eligibility transition

**Applies to:** the frozen October 11, 2026 ANAXI public reference distribution at
`reference-distribution-2026-10-11/` and GitHub Release
[`v2026.10.11-public`](https://github.com/whiteknave2-noah/anaxi-a-digital-kardia/releases/tag/v2026.10.11-public).
This erratum was established **after** that edition was published. The original
release tag, runnable distribution, provenance manifests, and source archives
remain unchanged.

## Observed failure and cause

An ordinary production conversation on October 12 was interrupted during
hippocampal index synchronization with
`HippocampusSourceDriftError`: a previously indexed item no longer had an
eligible source candidate. **The canonical source still existed and was
unchanged.** No model pass or model-input delivery occurred for the interrupted
submission, and the failed sync rolled back.

The October 11 code includes a non-monotone eligibility rule for an
authenticated human waking input (`H`). Context preparation can index the
input while it is standalone, before the response has been committed. A later
canonical waking event (`X`) can then lawfully link that `H` to a reply.
On the next sync, the linked input ceases to qualify as a standalone candidate.
The existing provenance guard correctly refuses an unexplained disappearance,
but this lawful transition was not accounted for. The public October snapshot
contains the pre-correction rule in `anaxi_final/hippocampus_store.py`.

The affected class includes ordinary linked human turns and relevant
continuation/recovery and correspondence-wrapping shapes. This was an
**index-eligibility / reconciliation defect**, not evidence that the canonical
conversation or historical source was erased.

## Private production correction and verification

The owner's private ANAXI production repository was corrected and deployed at
commit **`7c92169`** on October 12. **That private commit is not a revision
of this public GitHub repository and is not included in the frozen release.**

The correction makes incremental sync and fresh rebuild apply the same
source-based rule:

- Retire a standalone authenticated `H` index entry only when exact canonical
  linkage and faithful representation by the linked `X` are established
  through the existing reconstruction verifier.
- Otherwise preserve the authenticated `H` entry, including pending,
  ambiguous, incorrectly authored, or Caret-framed linkage; resemblance or
  mere substring containment does not prove supersession.
- Continue to fail closed for genuine source disappearance or immutable-field
  drift. Do not alter canonical history to repair a derived index.

Reported verification included regression cases that fail on the older code;
**288 passed, 5 skipped** across 21 affected test files; and a fresh
production-data replica. After authorized promotion, a controlled production
sync (without a waking turn or model inference) retired the one lawfully
superseded entry, added the **17 expected entries** (including **14
authenticated Caret-framed utterances**), preserved **1,864 unrelated index
entries**, and left canonical history unchanged. A repeated sync was
idempotent and a fresh rebuild agreed with the live index. The Caret additions
retained their existing attribution and disclosure boundaries across **224
authorization comparisons**, without an observed new disclosure path.
The owner accepted the demonstrated production failure class as **CLOSED**.

The exact-link verification adds approximately **347 ms** to the measured sync
with 318 linked inputs; its cost grows with linked history. This is a reported
tradeoff, not a claim of constant cost.

## Interpretation of the frozen public release

The independently verified October public reference run reported **374/374
publicly bound scenarios passing**. Those results remain a description of the
checks performed at that time; they **did not establish correctness of the
later-discovered standalone-to-linked source transition**.

The tagged public distribution intentionally preserves the original
historical source and can still exhibit the defect under the affected
multi-turn indexing circumstances. **This erratum documents the correction;
it does not silently patch the tagged reference package or claim that the
private fix is publicly runnable.**

No private messages, production databases, credentials, or native Porch
implementation are published by this notice.
