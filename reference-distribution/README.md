# ANAXI reference distribution A

## What this is

A privacy-safe, runnable reference copy of the finished ANAXI system at source
release `4e950d069885e0ec666244edd9d9d86f8d8640a1`, packaged so that someone
outside the original environment can reproduce the claims that can legitimately
be reproduced offline:

- every publicly bound scenario of the owner's completion inventory, each
  established by named offline tests and, for resource claims, by exact N==M
  assay records;
- the offline reference harness, which drives the real production modules through
  representative waking, recovery, Sleep and capability seams;
- the synthetic public-resource collection and its assay evidence, which can be
  regenerated byte for byte.

## What this is not

- Not the production system. Real conversations, correspondence, journals, notes,
  photographs, databases, logs, credentials and every private space are **absent**.
  People's names, account identifiers and host paths are replaced with synthetic
  stand-ins (for example the owner is "Alex"). No production or private state is
  needed, and none can be reached from here.
- Not a reproduction of live events. Requirements that can only be met by genuine
  live occasions are reported as **not reproducible locally**, never as passed.
- Not a portable, system-agnostic harness. This package is specific to ANAXI's own
  mechanisms. A later portable package follows the maxim
  *"Use the questions. Replace the mechanisms."* This package keeps ANAXI's
  mechanisms and is not that harness.
- Supported platform: **macOS with Python 3.14 only.** Linux and Windows are not
  claimed.

## Contents

| Path | What it is |
|---|---|
| `anaxi_final/` | ANAXI source and tests from the release. Some files carry deterministic synthetic replacements; `DISTRIBUTION_PROVENANCE.json` records which, by rule. |
| `anaxi_final/owner_completion_inventory.json` | The owner's capability and scenario inventory. |
| `anaxi_final/completion_evidence/scenario_bindings.json` | Public scenario bindings: which tests and artifacts establish each scenario. |
| `anaxi_final/completion_evidence/synthetic_public_resource*.json` | Assay evidence over the synthetic collection. |
| `reference_fixtures/public_resource_collection/` | Synthetic library, photograph and music collection, generated programmatically. |
| `reference/` | The public runner and the tools that regenerate the fixtures and evidence. |
| `DISTRIBUTION_*` | Provenance (per-file hashes and origin), manifest and status. |

### Synthetic fixtures

The collection holds a long multi-byte text document, a nested note, a text PDF,
an image-only three-page PDF, one photograph for each supported extension (jpg,
jpeg, png, webp, gif) and WAV, FLAC and WMA tracks of about six seconds. It keeps
the properties the resource claims test: nesting, continuation windows, text-less
PDF paging, pixel delivery, and late audio windows. It does not reproduce the
owner's collection, its size or its content. Claims about "every item" mean every
item of this collection.

## Setup (once)

You need macOS, Python 3.14 as `python3.14` (for example from python.org), and
network access for this section only. The download is large (it includes PyTorch)
and needs a few GB of disk.

```bash
cd path/to/this/distribution      # the directory that contains this README
python3.14 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python reference/run_reference.py setup-model
```

`setup-model` downloads the `all-MiniLM-L6-v2` embedding model (about 90 MB) into
`.hf_home/` inside this directory. Nothing is written to your home directory's
model caches.

## Run

```bash
.venv/bin/python reference/run_reference.py run
```

The run needs no network. The runner forces Hugging Face offline mode and runs the
tests under ANAXI's network guard, which blocks every non-loopback connection. It
takes a few minutes and writes everything to `reference_results/`:

| File | Content |
|---|---|
| `SUMMARY.json` | Every check and the overall verdict |
| `scenario_report.json` | Per-scenario and per-test-node outcomes |
| `ledger.json` | The ANAXI completion ledger over this run |
| `*.log` | Raw output of each step |

The runner performs, in order:

1. **Environment check**: macOS, Python 3.14, inside a virtual environment.
2. **Integrity**: every file matches `DISTRIBUTION_PROVENANCE.json` and nothing unexpected is present.
3. **Import isolation**: ANAXI modules load from this directory only.
4. **Synthetic resources**: the fixtures are regenerated and must be byte-identical; the unmodified ingest and assay code is re-run over them, and the evidence must be byte-identical to the shipped evidence.
5. **Reference harness**: `anaxi_final/reference_harness_v0.py`.
6. **Scenario accounting**: `anaxi_final/scenario_evidence.py` runs every bound test node; the completion ledger is then generated from the result.
7. **Integrity again**: the run must not modify the distribution.

### Expected result

```
overall: REPRODUCED
reproducible scenarios: 376/376 PASS, 0 FAIL (of 378 inventory scenarios)
NOT_ATTEMPTED (production-only): 2
live-only requirements not reproducible locally: <n>
withdrawn from the release contract: 27_boundary_inspection
```

The runner computes these numbers from the package; nothing is hard-coded. The
exit code is 0 only when the overall verdict is `REPRODUCED`.

## How to read the results

| Label | Meaning |
|---|---|
| **PASS** | A publicly bound scenario whose every bound test node passed in this run, and whose every bound artifact record is exact-complete (expected = attempted = passed > 0). |
| **FAIL** | A bound scenario with any failed, errored, skipped or missing node, or an artifact record that is not exact-complete. The node and the reason are recorded. |
| **NOT_ATTEMPTED** | A scenario with no public binding. In this package that is exactly the two production-only scenarios below. They are never counted as PASS. |
| **Live-only requirements** | Requirements that only genuine live occasions can satisfy. No live evidence ships, so they are reported as not reproducible locally. For that reason `ledger.json` reports `whole_system` as `NOT_COMPLETE`. That is the truthful local result, not a failure of the reproducible claims. |
| **Owner dispositions / withdrawals** | In production, the owner settled some live-only requirements by recorded decision. Those records are part of the unpublished live acceptance, so they are not reproduced here. One capability, `27_boundary_inspection`, was withdrawn from the release contract by owner decision. The ledger lists it under `release_contract.withdrawn_from_release`; its historical status is kept, never rewritten as passed. |

### The two production-only scenarios

| Scenario | Why it is not reproduced |
|---|---|
| `15_recovery_wtr0 / specific_h_…_assessed_without_fabrication` | A read-only recovery assessment of one specific production message against production history. The general recovery claims keep their offline tests. |
| `30_delivery_to_subject_at_production_sizes / every_real_public_resource_reaches_subject` | Defined to pass only on the owner's real collection. The synthetic delivery evidence supports the other delivery scenarios. |

Both are listed with reasons in `scenario_bindings.json` under
`public_distribution.omitted_production_only`. One Windows-launcher test node is
also removed from the bindings (`public_distribution.removed_nodes_for_excluded_surfaces`),
because Windows is outside the supported platform.

### Tests outside the public run

The run executes the bound test nodes and the reference harness, not the whole
historical test suite. A few unbound tests, such as
`anaxi_final/test_evidence_boundary.py` and `anaxi_final/test_live_acceptance_evidence.py`,
read production evidence that is deliberately not published. They are not part of
the public contract.

## Optional real-model harnesses

Files named `anaxi_final/test_real_model_*.py` are optional, opt-in harnesses. They
need a local Ollama installation with the model ANAXI uses, and they are enabled
only with `ANAXI_REAL_MODEL_HARNESS=1`. Their outcomes are probabilistic, and they
are **not** part of the offline reproducibility run, which skips them.

## Rerunning safely

```bash
.venv/bin/python reference/run_reference.py reset
.venv/bin/python reference/run_reference.py run
```

- `reset` removes `reference_results/` and Python caches, and keeps `.venv/` and `.hf_home/`.
- `run` also replaces its own previous `reference_results/` by itself.
- Test state is created in temporary directories and discarded.
- To start completely fresh, delete `.venv/` and `.hf_home/` and repeat Setup.
